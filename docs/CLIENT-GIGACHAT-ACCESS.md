# Доступ к GigaChat API — инструкция для заказчика

Что нужно: получить в личном кабинете Сбера ключ доступа и прислать его владельцу
сервиса. Занимает 5–10 минут, сервер и программист для этого не нужны.

Проверено 13.11.2026 по официальной документации: `developers.sber.ru/docs/ru/gigachat`.

---

## Шаг 1. Войти в личный кабинет

Открыть <https://developers.sber.ru/studio/workspaces/my-space/get/gigachat-api> и
войти по **Сбер ID**.

Подойдёт обычный аккаунт Сбера — отдельная регистрация для разработчиков не нужна.

## Шаг 2. Создать проект

1. В левом меню нажать **Создать проект**.
2. В разделе **AI-модели** выбрать **GigaChat API**.
3. Ввести название проекта — любое понятное, например «Научный агент».
4. Прочитать и принять пользовательское соглашение.

## Шаг 3. Получить ключ

1. В проекте слева открыть раздел **Настройки API**.
2. Нажать кнопку **Получить ключ** — откроется окно «Сохраните ваш Authorization Key».
3. **Скопировать и сохранить три значения** (они показываются только один раз):

   | Поле в кабинете | Зачем оно нужно |
   |---|---|
   | **Authorization Key** | готовый ключ: им подписывается запрос за токеном доступа |
   | **Client ID** | идентификатор проекта |
   | **Client Secret** | секрет проекта — это пароль, обращаться с ним как с паролем |

4. В правой панели проекта проверить поле **Scope**. Для физического лица там должно
   быть `GIGACHAT_API_PERS` — это и есть нужный тариф.

> Если кнопка **Получить ключ** неактивна — у вашей учётной записи роль
> «Наблюдатель». Ключ могут получить только **Владелец** и **Администратор**
> проекта. Нужно попросить владельца пространства выдать роль.

## Шаг 4. Прислать значения владельцу

Отправить три значения — `Authorization Key`, `Client ID`, `Client Secret` — тем
каналом, которым вы обмениваетесь доступами (менеджер паролей, защищённая ссылка,
звонок с последующей передачей частями).

**Не отправляйте их в открытые чаты и почту без защиты**: `Client Secret` — это
пароль от платного ресурса, и его утечка означает расход ваших токенов чужими
людьми.

## Что будет с вашими токенами

- Новый пользователь автоматически получает тариф **Freemium** — 365 000 000
  бесплатных токенов на генерацию текста.
- Токены распределены по моделям: 250 млн — Lite (`GigaChat` / `GigaChat-2`),
  40 млн — Pro, 25 млн — Max, 50 млн — Ultra.
- Срок действия бесплатных токенов — **12 месяцев** с момента подключения.
- Наш сервис работает на модели Lite и тратит порядка 50 тысяч токенов в сутки,
  то есть 250 млн хватит примерно на 13 лет непрерывной работы — ограничением
  будет не расход, а годичный срок действия.
- Если понадобится докупить токены: с 1 сентября 2026 года новые клиенты
  оплачивают пакеты на платформе `cloud.ru`. Для бесплатного режима это не нужно.

## Если ключ потерялся или произошла утечка

В том же разделе **Настройки API** нажать **Получить новый ключ**. При повторной
генерации кабинет спросит, сколько времени ещё будет действовать старый ключ —
максимум 250 минут. Этого достаточно, чтобы владелец сервиса успел заменить
значения без простоя.

## Что произойдёт после передачи ключа

Владелец сервиса:

1. впишет значения в закрытый файл настроек на сервере (в репозиторий они не
   попадают);
2. прогонит проверочный вызов к GigaChat с сервера;
3. покажет вам первый автоматический выпуск новостей и отчёт о расходе токенов.

Если проверка вернёт ошибку 401 или 403 — это означает неверный ключ или
неподходящий Scope, и значения нужно будет перевыпустить. Ошибки 402 и 429 —
это исчерпанный лимит, они лечатся тарифом, а не ключом.
