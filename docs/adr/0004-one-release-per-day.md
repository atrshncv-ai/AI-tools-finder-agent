# ADR 0004 — Один выпуск в сутки, бюджет проверяется на публикации

**Статус:** принято
**Дата:** 2026-11-10
**Требования:** R08, R08.1, R19, R18

## Контекст

Цикл крутился каждые десять минут. За сутки это давало до десяти частичных
выпусков: клиент видел, как подборка меняется в течение дня, а владелец —
несколько «финальных» сообщений. Ограничение `--daily-cap` действовало только на
одобрение в `app/scripts/hermes/evaluate-news.ts`; публикация
(`app/scripts/hermes/deploy-ready.ts`) не была ограничена ничем и публиковала всё,
что дошло до `summarized`. Ручная правка манифеста или прямой вызов публикации
давали лишние материалы. Переменная `HERMES_DAILY_CAP` управляла половиной
правила и путала.

## Решение

1. **Один выпуск в UTC-сутки.** `pipeline_state` хранит строку
   `cycle-YYYY-MM-DD` со `stage`. После `stage=published` цикл спит до следующих
   UTC-суток; повтор разрешён только при сбое, и он продолжает тот же цикл
   (`app/scripts/hermes/ralph-loop.sh`, `app/scripts/hermes/publish-budget.ts`).
2. **Бюджет дня `DAILY_BUDGET`** — 5..10, по умолчанию 8, значение вне диапазона
   останавливает конвейер на старте (`BudgetConfigError`), а не подменяется молча.
3. **Бюджет применяется дважды.** `app/scripts/hermes/manifest-gen.ts` берёт
   лучшие в пределах бюджета; `app/scripts/hermes/deploy-ready.ts` через
   `planPublication()` отказывает в публикации сверх бюджета или после
   зафиксированного выпуска (`already-published-today`,
   `daily-budget-exhausted`, `no-ready-articles`).
4. **Порядок отбора:** балл desc → уверенность судьи desc → свежесть desc → id.
   `HERMES_DAILY_CAP` удалён; `LINEAR_WORKER_INTERVAL_MS` теперь означает только
   паузу повтора после сбоя.

## Следствия

Плюсы:

- клиент получает один предсказуемый выпуск в день;
- бюджет нельзя обойти ни манифестом, ни ручным вызовом публикации;
- повтор после сбоя не создаёт второй выпуск;
- исчезла переменная, которая действовала только на половину правила.

Минусы и ограничения:

- при сбое после полуночи UTC выпуск дня может не состояться — это честное
  «сегодня нет», а не второй выпуск;
- кандидаты, не попавшие в бюджет, остаются `pending` с сохранённым вердиктом и
  копятся до `purge-stale`; судья за них повторно не платит;
- бюджет скачиваний и бюджет публикаций — разные числа, их легко перепутать:
  первый экономит токены и трафик, второй ограничивает продукт.

## Альтернативы

- **Оставить цикл каждые 10 минут.** Десять поводов для частичного выпуска.
- **Ограничивать только одобрение.** Проверено: публикация всё равно обходила
  лимит.
- **Считать бюджет только по `platformPublishedAt`.** Не видит зафиксированный
  выпуск при повторном запуске и позволяет второй выпуск в тот же день.
