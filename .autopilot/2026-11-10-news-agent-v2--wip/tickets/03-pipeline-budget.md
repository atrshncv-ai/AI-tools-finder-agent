## Что должно заработать

Материал, собранный из RSS, прогоняется через дешёвый префильтр по заголовку и лиду.
Только прошедшие идут к судье; страница скачивается уже после того, как материал признан
тематическим, и только для тех, кто попал в дневной бюджет. За сутки публикуется не больше
бюджета — лучшие по баллу, а не последние по времени. Счётчики цикла (собрано, отсеяно
префильтром, отсеяно судьёй, одобрено, опубликовано, причины отказа) видны в базе и в
служебном отчёте.

Цикл запускается один раз в сутки; повторный запуск в тот же день не создаёт второй выпуск.

## Из брифа, дословно

> «куча данных обрабатывалась впустую, либо наоборот - вообще не обрабатывалась»
> «выбирал самые крутые новости»
> «5–10 в день, жёсткий дневной бюджет»
> «раз в день (как и раньше) агент публикует набор собранных новостей»

## Критерии приёмки

- [ ] из 100 кандидатов страница скачивается не более чем для `DAILY_BUDGET × 3`
      (тест считает обращения к `fetch`)
- [ ] судья вызывается только для прошедших префильтр; его вердикт сохраняется
      в `metrics.judge` со всеми полями
- [ ] `manifest-gen` при 20 одобренных и бюджете 8 отдаёт 8 лучших по баллу
- [ ] `DAILY_BUDGET` вне диапазона 5..10 — ошибка конфигурации при старте, а не тихое значение
- [ ] счётчики цикла записываются в `pipeline_state.metrics`; миграция применяется на чистой БД
- [ ] второй запуск в тот же календарный день не публикует второй выпуск
- [ ] при отказе провайдера публикация не происходит, причина отказа попадает в счётчики
