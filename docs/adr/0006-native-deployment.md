# ADR 0006 — Прод разворачивается нативно: PM2 + systemd + nginx, без Docker

**Статус:** принято
**Дата:** 2026-11-10
**Требования:** R01, R02, R16, R04

## Контекст

В репозитории два пути запуска. Docker-путь (`docker-compose.yml`, `Dockerfile`)
поднимает postgres, веб и nginx, но **не содержит конвейера**: процесс
`hermes-ralph-loop` есть только в `ecosystem.config.cjs`. В образ не ставятся
`yt-dlp`, `ffmpeg` и `deno`, без них YouTube-поток и транскрипты не работают. Cron
дайджеста и бэкапа в compose тоже нет. При этом старый `docs/DEPLOY.md` описывал
Docker как единственный способ и упоминал LM Studio, локальный перевод и Kimi
OAuth — всего этого в коде нет.

Документация врала, а развёртывание по ней не давало выпуска.

## Решение

Прод — нативный стек на Ubuntu 24.04:

- Node.js 20 и `npm ci` в `app/`, сборка `npm run build`;
- PostgreSQL 16 как системная служба;
- PM2 по `ecosystem.config.cjs`: `news-agent-web` (`dist/boot.js`) и
  `hermes-ralph-loop` (`app/scripts/hermes/ralph-loop.sh`);
- nginx + certbot для HTTPS, proxy на `127.0.0.1:3000`;
- cron для дайджеста (06:00 UTC) и бэкапа (03:30 UTC);
- `app/.env` — единственный источник конфигурации, PM2 читает его сам.

Скрипты и runbook: `scripts/deploy/install.sh`, `scripts/deploy/cron.sh`,
`scripts/deploy/harden.sh`, `docs/DEPLOY.md`. Docker-файлы остаются в репозитории
как legacy и прямо помечены таковыми в документации; удалять их в этом прогоне не
стали, чтобы не ломать существующие привычки и внешние ссылки.

## Следствия

Плюсы:

- один способ запуска, совпадающий с тем, что реально работает;
- конвейер, `yt-dlp`, `ffmpeg` и cron живут там же, где веб;
- обновление — `git pull`, `npm ci`, `build`, `pm2 restart`, без пересборки образа;
- документация описывает факт, а не третий вариант.

Минусы и ограничения:

- сервер требует ручной настройки ОС (пакеты, пользователь, БД) — это делает
  `scripts/deploy/install.sh`;
- нет изоляции контейнеров: безопасность держится на `ufw`, `fail2ban`, SSH по
  ключу и обновлениях (`scripts/deploy/harden.sh`);
- Docker-путь может отставать от кода и не должен использоваться в проде.

## Альтернативы

- **Довести Docker до полного стека.** Пришлось бы ставить `yt-dlp`/`ffmpeg` в
  образ, описывать cron в контейнере и PM2-процесс конвейера; выгоды для одного
  сервера нет.
- **Оставить оба пути равноправными.** Именно это и породило документ, который
  врёт: читатель не знает, какой из двух путей настоящий.
